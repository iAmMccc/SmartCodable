# 覆盖率与变异测试指南

覆盖率用于发现尚未执行的代码路径，不证明行为正确，也不能代替独立的预期值和边界测试。行覆盖、区域覆盖、分支覆盖和条件覆盖是不同指标；报告未提供的指标不应推算为 100%。

## 收集覆盖率

在仓库根目录执行：

```sh
swift test --enable-code-coverage
swift test --show-codecov-path
```

SwiftPM 将构建产物和覆盖文件保存在当前包的 `.build` 目录。不同 SwiftPM 版本的产物布局可能不同，以 `--show-codecov-path` 的输出为准。使用 LLVM 工具查看详细区域和行信息时，应使用与生成 profile 的工具链兼容的 `llvm-cov` 和测试二进制。只比较相同工具链、源码范围和统计口径的结果；源码增删会改变分母。

运行失败、超时或测试被跳过时，应同时记录这些状态，不能把所得覆盖率当作完整通过运行。独立子进程可能产生单独的 profile；没有合并时，主进程报告不包含这些路径。

## 变异测试

变异测试通过有控制地改变实现、观察测试能否识别行为偏差来检查断言的敏感度。对每个变异：

1. 在隔离副本中先运行未变异的对照测试，确认测试数非零且结果符合预期。
2. 应用一个可编译的变异，再运行同一测试；记录编译失败、测试失败、超时及未检出等不同结果。
3. 分别处理等价变异和工具限制；有限的手工变异结果不代表整个项目的变异分数。

测试正确性的证据还包括明确输入、与实现独立的预期值，以及能够区分失败回退和正常解码的对照。原始字节 smoke、结构化性质和覆盖引导 fuzzing 的范围见 [测试契约](contracts.md) 与 [Fuzzing 指南](../../Fuzzing/README.md)。
